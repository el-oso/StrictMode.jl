StrictModeTest — the proofs ​

StrictMode reads inferred types and typed IR. It needs no other package, which is what makes it safe to depend on from src — and why its allocation verdicts report: typed IR still shows allocations LLVM later deletes, so there they can only say something looks wrong.

StrictModeTest is the other half. It goes in your test environment, brings AllocCheck, JET and TrimCheck, and throws — a violation fails the build. Keeping them apart means your users never install those backends just to use your package.

julia
# test/Project.toml:  [deps] StrictMode, StrictModeTest
using StrictMode, StrictModeTest

@test_noalloc kernel!(C, A, B)     # throws if AllocCheck finds any allocating path
test_compiled(MyPkg)               # gate everything the module actually compiled

The macro you write picks the engine. There is no mode to switch.

report (StrictMode)prove and gate (StrictModeTest)
@assert_noalloc f(x)@test_noalloc f(x)
@assert_noboxing f(x)@test_noboxing f(x)
@assert_typestable f(x)@test_typestable f(x)
@assert_trim_compatible f(x)@test_trim_compatible f(x)
@strict f(x)@test_strict f(x)
@kernel f(x)@test_kernel f(x)
findings(f, types)test_signatures(pairs)
audit(mod; sweep = true)test_compiled(mod)
—@test_steady_state f(x) — allocation that STOPS once warmed, measured
—@test_no_gc_pause f(x) — no collection runs while the call does, measured
—proof_findings(f, types) / proof_findings(mod) — proved, as data
—proof_audit(mod) — proved, as data
—test_registered()
audit(mod; require = :all)test_coverage(mod) — every method declared or visibly exempt
—test_exemptions(mod) — an opt-out the proofs no longer need
—test_calls(mod) — every reachable call resolves, including on a branch no test takes
—test_layers(L => (deps…), …) — a declared layer graph holds, both ways
—test_latency(pkg) — load time and first-call time, measured in a fresh process
StrictModeTest.StrictModeTest Module
julia
StrictModeTest

The proving half of StrictMode, for a package's test/ environment.

StrictMode analyzes with a value-free engine — inferred return types plus a scan of typed IR — that needs no backend and is cheap enough to run at load time. It reports: its allocation verdicts are structural guesses, so nothing in it can break a build. StrictModeTest adds the proofs — AllocCheck's static no-allocation analysis, JET's optimization analysis, and TrimCheck's juliac --trim=safe verifier — and it gates.

There is no preference to switch and no ambient state to read: which engine a call site uses is the macro you wrote.

report (StrictMode)prove and gate (StrictModeTest)
@assert_noalloc f(x)@test_noalloc f(x)
@assert_noboxing f(x)@test_noboxing f(x)
@assert_typestable f(x)@test_typestable f(x)
@assert_trim_compatible f(x)@test_trim_compatible f(x)
findings(f, types)test_signatures
audit(mod; sweep = true)test_compiled
—test_registered
julia
using StrictMode, StrictModeTest    # in test/runtests.jl

Loading this package requires StrictMode.checks_enabled(). With checks off every @assert_* is a bare call, nothing registers, and test_registered() would sweep an empty registry and report success — so it refuses to load rather than gate on nothing.

Proving macros ​

StrictModeTest.@test_noalloc Macro
julia
@test_noalloc f(args...)
@test_noalloc f(args...) types=(T1, T2, …)

Fail unless AllocCheck can prove f(args...) allocates nothing on any path.

This is the authoritative counterpart to StrictMode.@assert_noalloc, which reads typed IR and only reports. A violation here throws a StrictMode.StrictViolation, so it is what a test suite or a CI gate should use. Each argument is evaluated once and the macro returns the call's value.

Allocations on never-taken throw branches are ignored by default — see StrictMode.set_ignore_throw! — as is a call whose only allocation is a recognized one-time-init barrier (see set_ignore_barrier!).

julia
@test_noalloc dot3(a, b)              # ok
@test_noalloc grows_a_vector(1000)    # throws StrictViolation listing the allocation sites
StrictModeTest.@test_noboxing Macro
julia
@test_noboxing f(args...)

Fail unless AllocCheck proves f(args...) performs no boxing or dynamic dispatch, while allowing legitimate typed heap allocations (a Vector, a Memory, …). The proving counterpart to StrictMode.@assert_noboxing.

julia
@test_noboxing fill_buffer!(buf, xs)        # ok: allocates a buffer, but no boxing
@test_noboxing sum_runtime_index(htuple)    # throws: jl_get_nth_field_checked (tuple boxing)
StrictModeTest.@test_typestable Macro
julia
@test_typestable f(args...)

Fail unless f(args...) is type stable: the inferred return type is a single concrete type (or a small isbits Union), and JET's optimization analysis reports nothing.

StrictMode.@assert_typestable throws on the return-type layer too — that half is exact — but substitutes an IR boxing signal for JET, and only warns on it. This macro is the proof of that second layer.

julia
@test_typestable muladd(2.0, 3.0, 1.0)          # ok
@test_typestable pick(heterogeneous_tuple, i)   # throws: Union from runtime tuple index
StrictModeTest.@test_trim_compatible Macro
julia
@test_trim_compatible f(args...)

Fail unless juliac's own verify_typeinf_trim verifier accepts f(args...) for a --trim=safe build. The authoritative counterpart to StrictMode.@assert_trim_compatible's static scan, and unlike that scan it covers reachability-limit union-splits.

julia
@test_trim_compatible entrypoint(argv)
StrictModeTest.@test_steady_state Macro
julia
@test_steady_state f(args...)
@test_steady_state f(args...) warmups = 3 repeats = 2 fresh_task = true

Fail unless f(args...) allocates nothing once warmed: the call is made warmups times, then measured, and anything above zero bytes raises a StrictMode.StrictViolation.

This is the check for code @test_noalloc can never pass and should not: a workspace pool that allocates whenever it grows to a new high-water mark, an arena that folds slabs, any buffer that reaches a steady state after a bounded number of calls. :noalloc asks whether allocation is possible on any path, and for such code it always is, so an all-paths proof must report the growth path forever. The property the code actually has is about the call sequence — warm it and it stops allocating — which is settled by measuring.

So this is a measurement, and the distinction matters when you read a pass:

  • It covers the calls that ran, not every path. It says nothing about an argument shape it was not given, where @test_noalloc would have.

  • It is the counterpart to an exemption, not a replacement for one. Mark the function @strict_exempt :noalloc reason = "…" so the allocation is excused where a reader can see it, then assert the real property here.

fresh_task = true measures on a newly scheduled task. Use it to tell a pool from a per-task initializer: a pool that has reached its high-water mark allocates nothing for any caller and passes either way, while a OncePerTask accessor passes on the warming task and fails on a fresh one, because every new task pays again. That is the difference between "bounded" and "once per task", and it is only visible by choosing which task does the measuring.

repeats measures more than once and keeps the largest, for a pool whose growth is uneven.

julia
ws = Workspace()
@test_steady_state solve!(ws, A, b)                      # warmed, then zero
@test_steady_state scratch(ws) fresh_task = true         # fails if it is per-task

Each argument is evaluated once, before the warmup calls, so the same values are reused throughout.

StrictModeTest.@test_no_gc_pause Macro
julia
@test_no_gc_pause f(args...)
@test_no_gc_pause f(args...) samples = 1000 max_collections = 0 max_q99_ms = 1.0

Fail unless no garbage collection runs while f(args...) does.

This gates the axis the allocation proofs do not cover. @test_noalloc proves that this call allocates nothing, and that is necessary without being sufficient: Julia's collector stops the world, so a thread that allocates pauses an allocation-free kernel at its next safepoint. No analysis of the kernel can see the cause, because the cause is not in the kernel.

Measured, not proven. The call is warmed, then run samples times, and the collector's own counters say whether a collection landed inside a call. max_collections = 0 is the default because that is what the name asserts; raise it for a process you know is doing other work.

max_q99_ms adds a latency budget on top: the 99th-percentile call must come in under it. Leave it unset and only the collection count is gated, which is the deterministic half — a wall-clock threshold depends on the machine, so state it only where you know the machine.

julia
@test_no_gc_pause gemm!(C, A, B)                                   # no collection in the window
@test_no_gc_pause gemm!(C, A, B) samples = 2000 max_q99_ms = 1.0   # and a tail-latency budget

A failure names the budget it missed and reports the distribution, because the number you need in order to act — how long the worst calls took — is not in the verdict. For the non-gating form, and for the full report at the REPL, use StrictMode.gc_pause_report.

Each argument is evaluated once, before the warmup calls, so the same values are reused throughout.

StrictModeTest.@test_strict Macro
julia
@test_strict f(args...)

Fail unless f(args...) is both type stable and allocation-free — the proving counterpart of StrictMode.@strict for type stability and allocation-freedom; the owned-scratch check @strict also runs has no proving counterpart.

julia
@test_strict kernel!(C, A, B)
StrictModeTest.@test_kernel Macro
julia
@test_kernel f(args...)

Fail unless f(args...) is type stable, allocation-free and vectorized — the proving counterpart of StrictMode.@kernel. :vectorized is a best-effort LLVM-IR scan in both tiers (it observes compiled output, so it already gated); what this adds over @kernel is AllocCheck's proof for the allocation half and JET's for the stability half.

julia
@test_kernel axpy!(y, a, x)

Gating drivers ​

StrictModeTest.test_signatures Function
julia
test_signatures(pairs; guarantees = (:typestable, :noalloc)) -> Vector{StrictFinding}

Prove guarantees for an explicit list of (f, types) pairs, and throw a StrictMode.StrictViolation collecting every failure. Returns the findings when all pass.

It takes signatures, not values, which is why it exists alongside the @test_* macros: @test_noalloc gemm!(C, A, B) makes you build the arguments, while gating a 10000×10000 signature here costs nothing. It also needs no src/ annotations, so a test suite can list a library's guaranteed entry points without the library depending on StrictMode at all:

julia
test_signatures([
    (dot3, (NTuple{3,Float64}, NTuple{3,Float64})),
    (gemm!, (Matrix{Float64}, Matrix{Float64}, Matrix{Float64})),
])
StrictModeTest.test_compiled Function
julia
test_compiled(mod::Module; guarantees = (:typestable, :noalloc), only = nothing, exempt = ())
    -> Vector{StrictFinding}

Prove guarantees for every concrete method instance mod's functions have actually compiled (during your tests, a run, or the precompile workload), and throw a StrictMode.StrictViolation collecting every failure.

No annotation needed, but coverage is whatever executed, and a module that mixes hot and cold (plan-time) helpers will be noisy — cold helpers that legitimately allocate show up too. Scope it with only / exempt, each a collection of functions / name Symbols, a Regex matched against the (demangled) name, or a predicate f -> Bool. @strict_exempt names are always excluded, so exempt = r"^_plan" scales a mixed hot/cold library without a hand-listed set.

This is the gate. StrictMode.audit is the reporting counterpart for the same scope.

StrictModeTest.test_registered Function
julia
test_registered(; guarantees = nothing, modules = nothing) -> Vector{StrictFinding}

Re-prove every signature in StrictMode's mark-once registry — everything @strict_function, @strict module, or register_strict! declared — and throw a StrictMode.StrictViolation collecting every failure. guarantees = nothing uses each entry's own setting; pass a tuple to override.

The registry is process-global and keyed on (f, types) with no module of its own, so a dependency loaded from source in the same session (a Revise or dev setup) contributes its declarations too — and your gate would then judge its kernels. modules = [MyPkg] scopes the sweep by each registered function's defining module. Unscoped, the reported count is broken down per module so an unexpected one is visible rather than silent.

It reports how many signatures it proved, because the registry is populated at declaration time and an implausibly small count is the signal that something did not register. A declaration made in a package's own src/ is stored in that package, so it survives the package's cached load and is counted here; one made by a direct register_strict! call belongs to the session that made it.

StrictModeTest.test_coverage Function
julia
test_coverage(mod::Module; require = :all, only = nothing, exempt = ())
    -> Vector{StrictFinding}

Assert that every signature mod defines and has compiled is either declared or visibly exempt, and throw a StrictMode.StrictViolation naming each one that is neither.

A method that has compiled concrete signatures needs every one of them declared: a declaration names a signature, so declaring f(Float64) says nothing about an f(Int32) that reached the same body. A method nothing has compiled yet has no signature to name, and there this asks only whether some declaration speaks for it.

This is the gate for the thing the other drivers cannot see. test_registered re-proves what was declared and test_compiled proves what ran; neither notices a method that was never brought under StrictMode at all. Here a missing declaration is a failure, so forgetting one is a red test rather than a silent pass.

Its verdicts are facts, not inferences — a declaration either names a signature this method would be dispatched for, or it does not — which is why this gates where StrictMode's allocation verdicts only report.

require = :all counts every method, including those on foreign functions (Base.size, Base.getindex); :public counts only exported/public functions. Scope with only/exempt exactly as the other drivers do.

julia
# in runtests.jl, next to the drivers that prove the guarantees
StrictMode.register_strict!(MyPkg.kernel!, (Vector{Float64},); guarantees = (:noalloc,))
test_registered()                       # …the declared guarantees hold
test_coverage(MyPkg; exempt = r"^_plan")   # …and nothing is undeclared

Note

A declaration made by @strict_function inside a package's src/ counts here: it is stored in that package, so it survives the cached load this gate runs after. A package that annotates its source is therefore not told its own methods are undeclared.

StrictModeTest.test_exemptions Function
julia
test_exemptions(mod::Module; only = nothing) -> Vector{StrictFinding}

Report the exemptions in mod that the proofs now find unnecessary: code marked cold that satisfies the guarantee it was excused from.

An exemption is forever unless something looks at it. Code gets fixed, a buffer gets preallocated, and the opt-out stays — so the guarantee is off for a function that would now pass. This is the counterpart of declaring: test_coverage finds what nobody declared, and this finds what nobody un-excused.

Findings are :info and never failures, so this never fails a build. Two reasons: an exemption is a human's deliberate statement and removing it is their call, and a red test for tidy-up work is a new reason to switch the gate off.

It lives here, in the proving tier, because only a proof may say this. StrictMode's value-free scan is wrong in both directions on allocation, so "the scan no longer sees a problem" is a guess; acting on it would delete an exemption the proofs then fail. Each exemption is checked by AllocCheck, JET and TrimCheck, on the signatures the exemption covers.

An exemption that names no signature is checked against every concrete signature the function has compiled; one that names a signature is checked against that one. A function with nothing compiled cannot be judged and is reported as such.

StrictModeTest.test_calls Function
julia
test_calls(mod::Module; only = nothing, exempt = ()) -> Vector{StrictFinding}

Prove that every call reachable from mod's compiled signatures resolves, and throw a StrictMode.StrictViolation collecting every one that does not.

This is the hole the other gates cannot see. @test_typestable and the allocation proofs read optimized IR and answer performance questions — does this dispatch at run time, does it allocate. A call that cannot resolve at all is invisible to them: a MethodError on a branch no test happens to take passes every one. JET's call analysis (report_call) finds it before the branch is ever reached, which is the closest Julia analogue of a compiler that checks every line of every build.

Two report kinds are gated, MethodErrorReport and UndefVarErrorReport — a call with no matching method, and a name that is not defined. The others are deliberately dropped. Over StrictMode's own 569 compiled signatures there were 373 non-boolean-condition reports, nearly all a Missing from union-splitting a Vector{Any} that never holds one, against 3 distinct method errors; and an uncaught-exception report fires on any function that validates its arguments and throws, which is correct code. A gate whose output is mostly noise is a gate that gets switched off.

Scope is the same as test_compiled: the signatures that have actually compiled, so warm the kernels first. only and exempt filter by function name.

julia
test_calls(MyPkg)                                   # every compiled signature
test_calls(MyPkg; only = r"^kernel_")               # just the hot ones
test_calls(MyPkg; exempt = (:read_config,))         # a guard inference cannot follow

A failure can be a false positive, and the shape is specific: a guard that makes the bad path unreachable, written where inference cannot carry the refinement to the call. isnothing(ref[]) && (ref[] = build()) followed by a second load of ref[] is the common one — the check narrows the first load, not the second, so the value stays Union{Nothing,T} and every use of it reports. Binding the load to a local once fixes both the report and the type instability behind it.

StrictModeTest.test_layers Function
julia
test_layers(Layer => (deps...), ...) -> Vector{StrictFinding}

Prove that a declared layer graph holds, and throw a StrictMode.StrictViolation collecting every violation.

Julia has no orphan rule, and should not: extending Base.show for your own type is how the ecosystem composes. What the language cannot know is a project's intended direction of dependency — that the kernel layer must not reach up into the application layer, that two sibling layers must not extend each other. Declare it and this checks it.

julia
test_layers(
    App    => (Engine, Kernel),
    Engine => (Kernel,),
    Kernel => (),
)

Two rules:

  1. Extension follows the declaration. A method written in one layer may only extend a function owned by a layer that layer declared. Engine adding a method to Kernel.area is fine above; Kernel adding one to Engine.spin is not, and neither is a sibling reaching across.

  2. No layer reads another layer's implementation. A qualified access to a name the owning layer does not mark public or export is a violation whichever way the declaration points. A public name is the interface; anything else cannot be changed without breaking the reader.

Only the declared modules are judged. A call into Base, Core, or a package outside the graph is out of scope — measured on StrictMode itself, the underlying analysis returns 66 improper accesses, essentially all of them deliberate reads of Base and Core internals that this package exists to perform. Judging those would bury the layer violations the declaration is about. For that wider question use ExplicitImports.check_all_qualified_accesses_are_public and its siblings directly; this is deliberately the narrower check.

A module missing from the graph is not judged, so the graph is also the opt-in. A submodule answers to the layer it sits beneath rather than escaping the declaration.

The extension rule reads the method census, so it sees a method on a foreign function even though its name is bound elsewhere; the access rule parses the layer's source, so a layer with no file on disk contributes no access findings.

StrictModeTest.test_latency Function
julia
test_latency(pkg::Symbol; calls = String[], max_load_ms = nothing,
             max_first_call_ms = nothing, precompile = true) -> LatencyReport

Measure load time and first-call time for pkg in a fresh child process, and throw a StrictMode.StrictViolation if a stated budget is exceeded.

This is the axis none of the guarantees reach. They are all about the code a call runs; this is about the time paid before it runs — the load, and the compile tax on the first call of a signature. Both are properties of a cold process, so only a child can measure them.

Both budgets are opt-in, and deliberately so. A wall-clock threshold depends on the machine: the same package loads at different speeds on a laptop, a shared runner and a pinned host, so a default would fail honest code on a slow box and pass a regression on a fast one. State a budget only where the host is pinned. With neither budget given this measures and returns, and nothing can fail — use it that way to record the numbers before choosing them.

julia
test_latency(:MyPkg)                                      # measure, never fail
test_latency(:MyPkg; max_load_ms = 400)                   # a pinned host, a real budget
test_latency(:MyPkg; calls = ["MyPkg.solve!(ws, b)"], max_first_call_ms = 2_000)

calls are strings of Julia code run in the child after the package loads; write them fully qualified. max_first_call_ms applies to each call separately, and the failure names the one that missed. precompile = false skips building the cache first, for a suite that already loaded the package — see StrictMode.latency_report for what that costs and what the report then claims.

Proofs as data ​

StrictModeTest.proof_findings Function
julia
StrictModeTest.proof_findings(f, types; guarantees = (:typestable, :noalloc)) -> Vector{StrictFinding}

One StrictMode.StrictFinding per requested guarantee, computed with the proofs rather than StrictMode's value-free scan. f is never called. This is the data half of the gating API; test_signatures/test_compiled/test_registered add the raise.

julia
proof_findings(mod::Module; guarantees = (:typestable, :noalloc), only = nothing, exempt = ())
    -> Vector{StrictFinding}

Every concrete method instance mod's functions have actually compiled, proved and returned as data. The module-scope counterpart of proof_findings(f, types), and the non-raising counterpart of test_compiled.

Reach for it when you want the proofs but not the raise: test_compiled returns its findings only when everything passes and throws a StrictViolation carrying a formatted string otherwise, so it cannot hand you structured findings for a package that is currently failing — which is exactly when an agent wants them.

StrictModeTest.proof_audit Function
julia
proof_audit(target = :registered; guarantees = nothing, sweep = false,
            require = nothing, only = nothing, exempt = ()) -> Vector{StrictFinding}

StrictMode.audit with the proofs behind it: same targets, same scoping, and the same Vector{StrictFinding} back, and it likewise never throws and never sets an exit status. The only difference is the engine — AllocCheck, JET and TrimCheck instead of the value-free scan.

That is the whole point of it existing. audit's allocation verdicts are structural guesses, which is fine for discovery but means an agent cannot tell a real regression from noise; the test_* drivers prove but raise, so they cannot hand back findings for a failing package. proof_audit is the missing corner: proved verdicts, as data.

It costs what the proofs cost — roughly an order of magnitude more per method than audit — so scope a module sweep with only/exempt rather than pointing it at everything.

julia
using MyPkg, StrictMode, StrictModeTest
fs = proof_audit(MyPkg; sweep = true, exempt = r"^_plan")
nfailures(fs)        # proved failures, not guesses
StrictModeTest.AnalysisError Type
julia
AnalysisError <: Exception

Thrown when a backend call (JET's report_opt, in practice) fails outright while compiling (f, types), instead of returning a report. The usual cause: full inference visits every branch of a method regardless of which one is reachable at runtime for a given call, so a runtime-dead branch that reaches a @generated function whose generator throws (an @assert at generation time, rather than a guarded return :(throw(...))) fails analysis even though the function itself runs fine. Carries the checked target, the analyzed signature, and the original error, so the failure names what was being analyzed instead of surfacing as a bare exception raised from inside the backend.

Barriers, juliac patches, and engine divergence ​

ignore_barrier / set_ignore_barrier! decide whether a recognized one-time-init barrier is exempt from AllocCheck's all-paths proof. divergence_report / StrictDivergence run both engines on one signature and capture an IP-free record of any disagreement — anonymized signature shape, signal categories, and versions only — that you can send to the maintainers to fix the scan.

StrictModeTest.ignore_barrier Function
julia
ignore_barrier() -> Bool

Whether @test_noalloc/@test_noboxing exempt a call recognized as routing through a one-time-init allocation barrier (Base.OncePerProcess/OncePerThread, or a function registered via StrictMode.register_alloc_barrier!) from AllocCheck's all-paths proof. Default true. See set_ignore_barrier!.

StrictModeTest.set_ignore_barrier! Function
julia
set_ignore_barrier!(b::Bool)

Set whether a detected allocation barrier is exempt from AllocCheck's all-paths proof. false disables the exemption — a barrier-containing call then reds @test_noalloc exactly as it would without this feature, since AllocCheck's static proof sees the barrier's one-time allocation and has no way to know it is amortized. Clears StrictMode's findings cache.

StrictModeTest.juliac_patches Function
julia
juliac_patches() -> Bool

Whether trim verification applies juliac's own juliac-trim-base.jl / juliac-trim-stdlib.jl patches before running the verifier. Default false — applying them disables logging for the whole session. See set_juliac_patches!.

StrictModeTest.set_juliac_patches! Function
julia
set_juliac_patches!(b::Bool)

Set whether trim verification applies juliac's Base/stdlib patches first.

true makes the verifier check the same program juliac --trim=safe compiles, which is the only way to avoid issue #19's false FAILs (a ≥4-argument string interpolation on a reachable throw path is rejected without them). The patched verification runs in a subprocess, so the caller's session keeps its logging: juliac-trim-base.jl stubs Base.CoreLogging.current_logger_for_env, which silences every @warn and @info in whatever process applies it, and that process is now a throwaway child.

The child costs a Julia start, a package load and a patch application, paid once per gate: test_signatures, test_compiled and test_registered verify every signature they cover in a single child. A verification outside a gate — @test_trim_compatible, or proof_findings called directly — pays for a child of its own, which is why this is off by default rather than always on. A signature whose function cannot be reached in a fresh process — a closure, or something defined in a module the child cannot load — falls back to unpatched in-process verification with a warning naming the reason.

false (the default) verifies against stock Base in this process and accepts the false-FAIL class.

StrictModeTest.divergence_report Function
julia
divergence_report(f, types; guarantees = (:typestable, :noalloc, :noboxing, :inlined)) -> StrictDivergence

Run StrictMode's value-free scan and this package's proof on f for the concrete signature types, and return a StrictDivergence capturing every guarantee where the two disagree (one says pass, the other fail). The result is IP-free — anonymized signature shape, signal categories, and versions only — so you can send it to us to fix the heuristic.

isempty(result) is true when the engines agree. f is never called.

julia
d = divergence_report(myfun, (MyType, Vector{Float64}))
isempty(d) || StrictModeTest.save_divergence(d, "strictmode_divergence.txt")  # email us this file
StrictModeTest.StrictDivergence Type
julia
StrictDivergence

The result of divergence_report: an IP-free record of where the scan and the proof disagree. isempty(d.diverged) is true when the two engines agree. Safe to send to the StrictMode maintainers — contains no source, no user type names, and no field values. show it, or write it with StrictModeTest.save_divergence(d, path).

StrictModeTest.save_divergence Function
julia
StrictModeTest.save_divergence(d::StrictDivergence, path) -> path

Write the IP-free StrictDivergence report to path (plain text) for emailing to the maintainers. No source, no user type names — only the anonymized signature shape, signal categories, and versions.
